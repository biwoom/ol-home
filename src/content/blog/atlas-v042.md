ATLAS는 처음부터 단일 HTML 파일 하나로 배포된다. 의존성 없이, 네트워크 없이, 그냥 파일 하나를 더블클릭하면 열린다.

그런데 한동안 이 파일이 너무 커졌다. 평균 8.2MB. 빠른 편이라 할 수 없다.

## 무엇이 커졌나

분석해보니 세 가지 주범이 있었다.

1. **이미지**: Base64 인코딩 시 원본 대비 약 33% 팽창
2. **폰트**: 한국어 서브셋 없이 전체 Noto Sans KR 임베딩
3. **주석 데이터**: 빨리어·한자 주석이 각 구절에 중복 포함됨

## 접근 방식 세 가지를 시도하고 버렸다

### 시도 1: WebP 변환

이미지를 모두 WebP로 변환하면 30~40% 절감이 가능하다. 그런데 문제가 있었다 — WebP Base64를 오래된 브라우저에서 인라인으로 쓸 때 렌더링 실패 사례가 있었고, ATLAS의 오프라인 우선 원칙상 브라우저 호환성을 포기할 수 없었다.

### 시도 2: 이미지 외부 링크화

가장 쉬운 해결책처럼 보였다. `<img src="...cdn.../...">` 형태로 외부 링크를 쓰면 파일 크기는 즉시 해결된다. 그러나 이것은 ATLAS의 핵심 원칙 — "네트워크 없이 동작" — 을 정면으로 위반한다. 버렸다.

### 시도 3: CSS 변수로 중복 제거

주석 데이터 중복을 CSS 변수로 줄이려 했다. 흥미로운 접근이었지만, 빨리어 발음 표기와 한자를 CSS 변수로 관리하는 것은 오히려 유지보수를 어렵게 만들었다.

## 실제로 효과 있었던 것

결국 두 가지가 실질적인 절감을 가져왔다.

**한국어 폰트 서브셋화**: 실제 사용되는 글자만 추출해 임베딩. 전체 Noto Sans KR (약 2.8MB) → 사용 글자 서브셋 (약 280KB). 90% 절감.

**이미지 품질 재조정**: 스캔 이미지 기준 JPEG 품질을 85 → 72로 낮추되, 육안으로 차이를 확인하며 진행. 평균 40% 절감.

## 결과

| 지표 | 이전 | 이후 |
|------|------|------|
| 평균 파일 크기 | 8.2MB | 3.4MB |
| 폰트 크기 | 2.8MB | 280KB |
| 이미지 크기 | 4.1MB | 2.5MB |
| 기타 | 1.3MB | 0.65MB |

3.4MB는 여전히 크다. 하지만 단일 파일로 한 권의 책과 도구를 함께 배포한다는 점을 고려하면 납득 가능한 크기라 판단했다.

다음 목표는 2MB 이하. 서브셋화를 빌드 파이프라인에 통합하고, 이미지 압축을 자동화하는 것부터 시작할 것이다.
